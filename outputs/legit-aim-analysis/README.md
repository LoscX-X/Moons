# Minecraft legit 瞄准数据分析

分析日期：2026-09-15。输入为本地 `legit.csv`，完成全量字段检查、连续性检查和差分重算，再在固定随机样本上分析分布并训练小型预测基线。原 CSV 未修改。

## 结论

这份数据可以用于研究瞄准动作的时间关联和构建离线轨迹预测基线，但不能直接照搬原加速度列训练。

1. **`accel_yaw` 是反向差分，`accel_pitch` 混用了两轴历史值。**已用原始角度重新计算步长和高阶差分。
2. **相邻步长存在明显延续性。**Yaw、Pitch 的一阶滞后相关系数分别为 0.717、0.671；历史两步的回归预测优于直接沿用上一步。
3. **两轴需要分别建模。**Yaw 步长分布明显宽于 Pitch；两轴带符号相关很弱，绝对幅度则存在相关。
4. **不能用一组速度/加速度分位数代表完整瞄准。**接近目标、转向中、停止和不同 UUID 组的分布都有差异。
5. **基线只能证明预测信号存在。**随后补做的合成闭环检查见第 8 节，暴露了目标输入不足；尚无游戏内验证，也没有训练能独立稳定追踪的神经网络。

## 2. 原加速度列的实际问题

记当前行为 k，上一条同 UUID、同序列记录为 k−1。在 **20,041,179 条**时间间隔为正且不超过 250 ms、可比较的记录上：

```text
原 accel_yaw[k]   ≈ delta_yaw[k−1] − delta_yaw[k]
原 accel_pitch[k] ≈ delta_pitch[k−1] − delta_yaw[k−1]
```

这两个关系在 0.01° 容差内全部成立。实测最大残差分别约 0.00005° 和 0.00004°。

第一项与通常的“本次步长减上次步长”符号相反，而且没有时间单位换算。**第二项不是俯仰加速度，是上一行 Pitch 步长减上一行 Yaw 步长。**此前抽样阶段对“两轴可能都是反向差分”的猜测，已被全量检查修正。

另外：

- 7,405 行原 delta_yaw 的绝对值超过 180°；在可比较记录里，7,135 行与最短弧 Yaw 差分相差超过 0.01°。这包含绕角域边界的情况，不应当作普通高速转头。
- delta_pitch 在可比较记录上均与原 Pitch 差分一致，容差 0.01°。
- sensitivity 范围为 −63 到 230；12,873 行小于 0，1,140,365 行大于 100。**大于 100 本身不证明错误**，可能存在不同百分比尺度；当前缺少定义，所以没有按游戏灵敏度直接换算，也没有把它放入训练特征。

本次模型不读取 `accel_*`，训练标签与历史步长均从 yaw/pitch 重新计算。

## 3. 清洗口径与抽样

全量流式读取，每块 300,000 行；跨块保留每个 UUID 最近三条记录。分布分析使用以下较保守子集：

- 连续四条观察不跨 new_sequence，相关三个时间间隔均为 40–60 ms。
- 数值有限，当前步长与提供的 delta 列一致到 0.01°，Pitch 在物理范围内。
- 本次及前两次最短弧 Yaw 步长不超过 90°、Pitch 步长不超过 60°，避免把大跳变混入常规动作统计。

符合条件的有 **17,003,128 行，占全量 83.59%**。其中两轴同时为零的比例为 **12.24%**。这些零值可能包含真实停止、量化及记录机制影响，不能全部解释成人为停顿。

在该子集里以固定随机种子 20260915 均匀抽样，要求前一时刻水平目标距离大于 0.05，最终保留 **400,000 行，覆盖 2,169 个 UUID 组**。以下分位数、相关系数和模型结果来自此样本；全量计数来自全部记录。抽样按记录加权，长记录组贡献更多，不等同于每名玩家等权。它还排除了大跳变，因此分位数不能代表原文件所有动作的极端尾部。

## 4. 发现了哪些规律？

### 4.1 幅度分布不对称，Yaw 明显更大

以下为绝对值；P95 表示样本中约 95% 不超过该值，并非建议上限。

| 指标 | 中位数 | P95 | P99 |
| --- | ---: | ---: | ---: |
| Yaw 步长，°/次 | 1.295 | 17.605 | 41.658 |
| Pitch 步长，°/次 | 0.818 | 6.699 | 12.194 |
| Yaw 相邻步长变化，°/次² | 1.119 | 13.229 | 29.996 |
| Pitch 相邻步长变化，°/次² | 0.658 | 5.340 | 10.121 |
| Yaw 步长的二阶差分，°/次³ | 1.539 | 17.019 | 37.336 |
| Pitch 步长的二阶差分，°/次³ | 0.833 | 6.690 | 13.286 |

这里“次²、次³”指按更新序号计算的离散差分，没有假装全部间隔严格相等。只有固定 50 ms 时，步长变化乘 400 才对应 °/s²，二阶步长差分乘 8000 对应 °/s³。

按每条实际记录间隔计算的平均角速度，Yaw 的 P95 约 352.6°/s，Pitch 约 134.0°/s；这仍受时间戳记录机制影响。不能把这些分位数直接设置成“真人硬限速”。

### 4.2 历史比每次独立随机更有信息

| 相关性 | Pearson r |
| --- | ---: |
| 本次 Yaw 步长与上次 Yaw 步长 | 0.717 |
| 本次 Pitch 步长与上次 Pitch 步长 | 0.671 |
| 本次带符号 Yaw 与 Pitch 步长 | 0.025 |
| 本次 Yaw 与 Pitch 步长绝对幅度 | 0.411 |

这说明在该样本中，两个方向的动作有明显时间延续性；水平和俯仰并不是必须同向变化，但大动作的幅度存在共同变化。**相关性本身不能证明某种运动模型或特定人的意图。**如果尝试学习轨迹，应保留时间窗口，不能把每次 yaw/pitch 随机抽样当作等价替代。

### 4.3 误差较大时，常规转向步长通常增大

采用 Minecraft 常用水平坐标约定，计算上一时刻目标实体坐标相对位置的水平朝向，再减去上一时刻 Yaw。只分析水平，避免臆定 position_y 的眼高。

| 上一时刻水平参考误差 | 本次 Yaw 步长绝对值中位数 | P90 |
| --- | ---: | ---: |
| 0–1° | 0.374° | 3.602° |
| 1–3° | 0.547° | 4.198° |
| 3–5° | 0.900° | 5.381° |
| 5–10° | 1.460° | 7.368° |
| 10–20° | 2.650° | 11.320° |
| 20–45° | 5.072° | 19.148° |
| 45–90° | 7.981° | 35.280° |
| 90–180° | 0.649° | 28.484° |

最后一档不延续单调规律，说明不能把所有记录套进“误差越大就越快追目标”的单一公式。目标位置插值偏差、转向意图和记录场景混合都可能影响结果，目前无法分清各自贡献。这里的“参考误差”不是经过射线验证的真实瞄准误差。

### 4.4 UUID 组之间也有差异

在至少 1000 条子集记录的组中，每组先计算平均绝对步长，再看组间分布：Yaw 的组均值中位数为 3.939°/次，组间 P90 为 6.384°/次；Pitch 对应 1.680、2.676°/次。单一全局参数可能混合了不同会话/用户/场景，不能将总体统计称为每个人的规律。

## 5. 实际训练了什么？

本次做的是 **一步预测的岭回归基线**：用历史预测下一次 Yaw/Pitch 步长。岭回归是带系数约束的小型线性模型，便于判断数据是否具有可学习的信号。

- 历史模型输入：前两次两轴步长，共四项。
- 几何模型另加入：上一时刻水平参考误差、水平距离、误差的带符号平方根。
- 未输入当前角度、当前目标位置、当前时间间隔、UUID 数字编码或原 accel 列；避免直接偷看当前动作标签。未知含义的 sensitivity 也未使用。
- 根据 UUID 的 SHA-256 哈希划分约 70%/15%/15% 的组，训练/验证/测试无 UUID 交叉。实际样本行比例受不同组大小影响。
- 训练 301,016 行 / 1,523 组；验证 47,703 行 / 325 组；测试 51,281 行 / 321 组。验证集从六档正则化系数中选择，测试集只作最终评估。

UUID 的真实含义未确认，所以这能排除相同 UUID 跨集合，不能保证同一个自然人绝不以不同 UUID 出现在不同集合。采样筛选也限制了结论的适用范围。

### 测试集结果

MAE 为平均绝对误差，RMSE 为均方根误差，越小越好。单位均为 °/次。

| 一步预测方法 | Yaw MAE | Pitch MAE | Yaw RMSE | Pitch RMSE |
| --- | ---: | ---: | ---: | ---: |
| 总是预测 0 | 4.251 | 1.756 | 8.965 | 3.147 |
| 直接沿用上次步长 | 3.229 | 1.397 | 6.611 | 2.579 |
| 前两步历史回归 | **2.921** | **1.203** | 5.782 | 2.136 |
| 历史 + 水平几何回归 | 2.957 | 1.205 | **5.587** | **2.136** |

历史模型相对沿用上次步长，Yaw/Pitch MAE 降低 **9.53% / 13.89%**。每个测试 UUID 等权后的 MAE 为 2.723 / 1.161°/次。几何输入降低了 Yaw RMSE，但没有改善 MAE，所以不能声称加入目标坐标使所有指标都变好。

系数已保存为 [ridge-baseline.json](E:/McEnv/moons/outputs/legit-aim-analysis/ridge-baseline.json)，用于复核这个离线实验。**它尚不能作为完整瞄准控制器使用：**一步误差小不代表连续反馈后稳定；第 8 节补充了简单合成闭环检查，仍未验证命中盒、遮挡、量化输出、目标切换或丢帧。

## 6. 下一步值得训练什么？

优先做 **条件轨迹预测**，再验证长时间回放：

1. 先完善来源不确定性处理，保留序列边界、时间间隔、目标插值风险标记，进一步区分静止、追踪和大转向。
2. 用过去 16–32 次两轴步长作为窗口，比较小型 [GRU](https://arxiv.org/abs/1412.3555) 或 [TCN](https://arxiv.org/abs/1803.01271) 与当前历史基线。它们分别用循环状态或时间卷积保留历史；这两篇论文是模型方法依据，不证明它们在本数据集上的效果，具体窗口长度是下一阶段实验选择。
3. 若需要生成动作，预测“给定历史和目标状态后的下一步分布”比只回归平均步长更值得评估；需要单独处理零动作、方向和幅度。只模仿均值可能把真实停顿抹掉。
4. 用完全隔离的 UUID/序列进行多步回放，检查误差积累、超调、速度/加速度/jerk 分布和量化后的轨迹；单步 MAE 只是第一项指标。

只有 legit 文件时，可以做预测、自监督表示或正常数据的一类建模，不能声称已经训练出区分作弊的可靠二分类器。若以后使用作者的合成 cheater 数据，相同原始 UUID/序列及其合成版本应进入同一数据划分；还需要独立真实来源的外部评估，避免只识别生成算法的痕迹。

对当前 SilentAura 的直接启示是：先把 Yaw/Pitch 响应、速度、加速度的定义与时基分清，保留真实发送历史，再做条件分布对照。**不能把 P95/P99 当成安全阈值，也不能仅靠降低速度或添加 Gaussian 就断定动作更接近这份数据。**本轮没有把训练结果接入游戏。

## 8. 模型在哪里、怎样调用、能否初步使用？

模型文件为 [ridge-baseline.json](E:/McEnv/moons/outputs/legit-aim-analysis/ridge-baseline.json)，2489 字节。它包含两套岭回归系数，以及各自的输入均值/标准差；两套模型共 26 个回归系数。它不是已经训练好的 GRU 或 Transformer，数据文件大不意味着回归模型也大。

新增纯 Python 推理入口：[infer_aim_baseline.py](E:/McEnv/moons/tools/analysis/infer_aim_baseline.py)。不需要 NumPy、PyTorch 或联网；加载 JSON 后即可计算。

在仓库根目录运行（已有 Python 可用时）：

```powershell
python tools/analysis/infer_aim_baseline.py predict --previous 4 1 --older 3 0.8
```

上一次步长为 Yaw=4°、Pitch=1°，上上次为 Yaw=3°、Pitch=0.8°时，history 模型预测下一步约为 **Yaw=2.82918°、Pitch=0.62178°**。参数顺序始终为 yaw、pitch，较新的一组放 previous。输出单位是度/次；模型没有 dt 输入，不能原样每个渲染帧都执行。

Python API：

```python
from tools.analysis.infer_aim_baseline import AimBaseline

model = AimBaseline(variant="history")
yaw_step, pitch_step = model.predict(previous=(4, 1), older=(3, 0.8))
```

geometry 版本另外需要上一条观察的水平目标误差和水平距离。推理入口已经与训练时矩阵计算对比：1000 条真实样本 × 两种模型，最大数值差约 1.07×10⁻¹⁴。它返回原始预测，不擅自加入限幅、随机偏移或量化。

### 8.1 连续把预测反馈给模型，会怎样？

执行了四组简单合成检查：目标固定为 Yaw=90°、Pitch=45°，水平距离 3 格；连续 100 次更新，每次将预测步长作为下一次历史。以下从静止开始的两组最有代表性：

| 模型 | 最终 Yaw | 最终 Pitch | 合成目标误差 |
| --- | ---: | ---: | ---: |
| history | −10.87° | 0.44° | 110.27° |
| history_geometry | 89.20° | 2.32° | 42.69° |

这不是数据集真实轨迹回放，也没有限速器、灵敏度量化或游戏几何；它检查的是预测器自身能否承担控制器职责。第一种模型不输入目标方向，不能独立追踪，偏置还会在连续运行中积累。第二种能产生水平跟随，但没有目标 Pitch 输入，因此无法可靠完成俯仰追踪。以非零历史初始化的另两组也没有进入 1° 目标误差。

详细结果：[closed-loop-probe.json](E:/McEnv/moons/outputs/legit-aim-analysis/closed-loop-probe.json)。复现命令：

```powershell
python tools/analysis/infer_aim_baseline.py probe --output outputs/legit-aim-analysis/closed-loop-probe.json
```

**初步用途**是离线一步预测、轨迹分析，或未来旁路记录预测与实际输出作比较。当前不适合作为 SilentAura 的完整转向控制器；尚未将模型接入功能代码。

## 9. 下一种模型，以及在什么过程接入

### 9.1 建议训练小型条件 GRU

GRU 用内部状态记住一段动作历史。建议先试单层、48 隐藏单元、16 次观察窗口，输出下一次两轴角度变化。下面是候选设计，并非已经训练或验证的模型。

每条观察可包含 10 项：目标 yaw/pitch 误差、最近一次 yaw/pitch 步长、两轴步长变化、两轴目标方向变化率、距离、Δt。输入必须来自当时已经可观察的状态，不使用下一次动作完成后的信息。

按带双偏置的单层 GRU(10,48) 加 Linear(48,2) 计算，共 **8738 个参数**，FP32 权重约 34.1 KiB，不含归一化、元数据和推理运行库。这个数量按 [PyTorch GRU 参数形状](https://docs.pytorch.org/docs/2.14/generated/torch.nn.GRU.html)推算，只用于说明候选模型规模，不是效果或性能保证。之后是否扩大，需要比较验证集与连续回放的收益。

当前 Kaggle 数据缺乏明确的眼高/瞄准点语义，因此完整目标 Pitch 误差不能直接可靠构造。可以先利用其历史动作序列做预训练实验；完整条件模型则需要核实或补采输入语义一致的记录。单纯把现有回归扩大成神经网络不会补出缺失的目标信息。

### 9.2 接在转向控制阶段

建议的新流程：

```text
选敌
  → Center / Closest
  → Lazy / Gaussian 和必要的预测、可用点检查
  → 计算目标 yaw/pitch，形成观察状态
  → Learned 策略：GRU 预测下一步 Δyaw / Δpitch
  → 统一速度、加速度约束，并结合鼠标量化选择可行输出
  → 正常提交、攻击射线检查和发包
  → 记录实际发送角度，更新历史
```

模型决定本次转向动作，不负责选择攻击对象、生成 AimPoint 或判断能否攻击。这里的统一四轴预算入口是重构设计，当前 Optimize 仍只是原预算策略的开关。

### 9.3 怎么从 Python 训练结果变成 Java 中可用的模型？

训练在独立 Python 工具中完成，导出 ONNX 文件及输入归一化、字段顺序、单位、采样周期和模型版本；Java 在本地加载并推理。ONNX Runtime 提供 [Java/JVM 推理接口](https://onnxruntime.ai/docs/get-started/with-java.html)。这里只确定可行路线，尚未添加此运行库，也未测试本客户端的打包和类加载兼容性。

实施顺序建议为：完成条件与序列数据准备 → 训练并导出 → Python/Java 同输入输出对齐 → 连续回放 → 客户端旁路记录预测 → 再评估实验控制模式。这样可以分别定位模型误差、导出误差和限幅/量化造成的变化。
