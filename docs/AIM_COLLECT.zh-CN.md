# 玩家战斗瞄准与移动数据采集

每次加载默认关闭，只观察附近其他玩家，不修改玩家动作或发送游戏包。

```text
.collect on
.collect off
.collect
.collect save locate
.collect save locate E:\AimData
.collect save locate "E:\Training Data\Aim"
```

`.collect` 显示状态、写入样本数、丢弃数和目录占用。`save locate` 不带参数显示目录，带绝对路径设置并记住目录；切换时旧队列异步保存完毕后，新会话写入新目录，不搬动旧文件。默认目录为 `MOONS_HOME/config/datasets/aim`。

## 什么时候保存

- 开启后仅在内存滚动缓存最近 **5 秒**的实体包快照；未发生战斗的缓存过期即丢弃。
- 服务端伤害包明确指向两个不同玩家时，补存双方最近 5 秒尚未保存的记录，随后持续保存双方的包。第三方玩家的预录不会被一同导出，本地玩家不作为采集主体。
- 只有挥手、转头、走路、自伤、环境伤害不会触发战斗。首次伤害之前没有超过 5 秒的追踪历史；没有成功造成伤害的对打不会导出。
- 默认最后一次 PvP 伤害后 **3 秒**结束窗口，期间新伤害会续期。超时后的数据重新只进入预录缓存。连续伤害不会重复保存已导出的预录。
- `.collect off` 丢弃未触发战斗的预录，异步排空已确认的写入队列。换世界、断线、切目录产生新会话。正常关闭会排空队列；强制结束游戏进程可能丢失尚未刷盘的数据。

实验分类中的 `AimCollect` 同样可控制开关和参数：观察距离默认 32 格（8–128），目标搜索距离默认 8 格（2–32），战斗结束等待默认 3 秒（1–5）。最多跟踪观察距离加目标距离内、离本地玩家最近的 64 名玩家。

## 数据与时间

UTF-8 JSONL，约 32 MB 分片，文件名包含 UTC 日期时间、随机会话编号、分片号。每片以 `type=session` 开始，数据行为 `type=sample`，正常结束时可有 `type=end`；训练时按类型过滤，不能把元数据当样本。

| 字段 | 含义 |
| --- | --- |
| `session`、`sample.combatId` | 会话和该玩家战斗段编号；战斗编号是单调时钟值，只在当前会话内解释 |
| `phase` | `pre_roll`：开打前的预录；`combat`：已确认的战斗窗口 |
| `sample.receivedEpochMillis`、`sample.appliedEpochMillis` | 接收、应用时的 Unix 毫秒；接收时间缺失为 -1 |
| `sample.receivedNanos`、`sample.appliedNanos` | 单调时钟，用于间隔、排序；不是服务器时间，不能跨进程比较 |
| `sampleTimeUtc` | 应用时刻的 UTC ISO 时间字符串 |
| `combatStartEpochMillis`、`combatUntilEpochMillis` | 当前段开始及本条记录已知的截止时间；后续伤害会延长截止时间 |
| `sample.worldTick`、`sample.sequence` | 客户端世界 tick 与写入顺序号；网络不是固定 20 Hz，不能靠行号替代时间 |
| `receiveToApplyMs` | 从网络接收到客户端应用的等待时间，包含本地延迟包模块影响 |
| `sample.packet`、变化标志 | 移动、身体转向、头转向、位置同步、传送、动画或伤害包，以及包实际携带的维度 |
| `sample.observer` | 采集主体的实体 ID、UUID、解码位置、眼高、包围盒、身体/头部 yaw、pitch、地面状态、姿态、潜行/疾跑及 Tab 延迟 |
| `sample.candidates` | 同一观察时刻的附近玩家快照，包含可能成为目标的本地玩家 |
| `observedVelocity`、`observedAcceleration`、`horizontalSpeed` | 由连续位置包差分得到的观测运动，单位格/秒和格/秒² |
| `movementDtSeconds`、`movementClock` | 位置包间隔；优先收包时钟，缺失时退回应用时钟，不能当作对方真实输入速度 |
| `bodyYawDelta`、`headYawDelta`、`pitchDelta` | 相邻该玩家样本间角度变化，yaw 跨 ±180° 正确归一化，单位度 |
| `groundTransition` | `landed`、`left_ground`、`none`；离地不等同于确认跳跃 |
| `sample.combatOpponentId`、`sample.damageTargetId` | 最近伤害证据涉及的对手，以及本条伤害包的受害者；不是确认的准星目标 |

位置包在客户端 APPLY 边界、原版修改实体之前按其位置编码基准解码，避免使用平滑渲染位置作为原始轨迹。线程间只传不可变快照。姿态、包围盒、Tab 延迟等是该时刻客户端已知值，不是每个移动包都携带；`positionNanos/rotationNanos/headNanos` 标记各维度最后更新时刻，-1 表示初始化值。`rotationKnown/headKnown` 表示本会话内是否已观察到对应转向包。

## 目标点位

后台保存最多 3 个候选目标，按视线包围盒相交距离优先，其次按 30° 锥形范围内点位的角度误差排序。每个候选保留：

- 眼睛，以及包围盒高度 0%、25%、45%、60%、75%、90%、100% 的脚、膝、骨盆、腹、胸、头、顶点。
- 包围盒的 8 个角点、距观察眼睛最近的盒上点、距有限视线最近的盒上点。
- 视线与包围盒相交时的交点。

通常 18 个点，发生相交时 19 个。各点都有世界坐标、相对观察眼睛的偏移、距离、yaw/pitch 误差和空间夹角。除眼睛外，人体部位是包围盒比例点，不是模型骨骼定位。

标签为 `ray_box_inferred`、`cone_inferred` 或 `none`。实体包不能确认对方准星目标，也不能确认墙体遮挡；统一保留 `occlusion=unknown`，不宣称命中或可见。头部 yaw 优先作为几何瞄准方向，身体 yaw 单独保留，缺失已知 pitch/yaw 的样本不推测目标。

## 容量与质量

- **每个保存目录硬预算 50,000,000,000 字节（十进制 50 GB）**，包括历史文件、元数据和其它已有文件。开始会话和换分片时重新统计，每行写入前检查预算；满额停止，不覆盖、不删除旧数据。
- 一个目录只允许一个本采集器写入；不要同时用其它程序向该目录写大文件。更换目录会使用新目录的预算，旧目录的数据需自行管理。
- 预录缓存最多 2048 条快照，写入队列最多 2048 条。拥挤或慢盘时不会阻塞游戏线程；提前挤出的预录计入 `sample.preRollEvicted`，队列丢样计入 `droppedTotal` 和状态栏。因此超高包量时预录可能短于 5 秒，不静默假装完整。
- `continuous=false`、传送/位置同步断点、序号缺口、时间间隔过大、战斗段变化都需要切断训练序列。队列缺口清空运动差分状态，不把丢失的轨迹连接起来。
- `sample.candidatesTruncated` 表示附近跟踪人数达到上限。初始未知值、缺失收包时间、客户端状态延迟、远端包量化和网络抖动都应纳入清洗规则。不能将远端观测直接标为真人鼠标输入或无辅助操作。
- 先按 `session + observer.uuid` 分组，再按该玩家的单调时间排序并切段；后来补存的另一玩家预录可能比文件前一行更早。数据集训练/验证应按玩家与会话分组，避免相邻轨迹泄漏。

验证：`gradlew.bat verifyAimCollect` 覆盖预录过期、参战双方筛选、战斗续期与去重、缓存限额、目标几何、时间差分、异步关闭、分片、历史数据预算和写盘错误。

现有 `tools/aim_training/prepare.py` 使用另一种 CSV 格式。本采集器输出带时间、候选点和质量标记的 JSONL；后续训练需要按上述分组和断点规则编写对应的预处理，保留推测标签的来源。
